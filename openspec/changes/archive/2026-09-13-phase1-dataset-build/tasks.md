- [x] 4.2 Implement the 3x3 Sentinel-2-patch-per-MapBiomas-pixel alignment (design.md decision), verified by spot-checking a known forest/pasture boundary for correct block alignment — `scripts/06_align_3x3_patches.py`. Mechanism: reproject MapBiomas onto Sentinel-2's own projection at 30m (nearest-neighbor); since 30m = 3x10m and the origin is S2's own grid, each label cell exactly covers a 3x3 S2 pixel block, no separate alignment math needed
- [x] 4.3 Verify reprojection/alignment correctness at the pixel level before building the full dataset (design.md risk), verified by a manual QA pass on a sample of labeled patches — 5 real bosque/pasto boundary points found via `stratifiedSample` (not arbitrary points) and spot-checked; all 5 patches show real spatial variation (e.g. point 4: 568-1146 DN range) consistent with a true class transition under the label cell. Bug found and fixed along the way: plain `.sample()` misses sparse masks (this boundary mask is ~1.5% of the AOI) unless you request far more candidates than needed — switched to `.stratifiedSample()`

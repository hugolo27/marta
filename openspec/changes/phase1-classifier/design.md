## Context

See `proposal.md` - Why. This design covers how the Random Forest baseline and CNN candidate get trained and compared, and how the two evaluation passes (test split, held-out generalization) fit together. It assumes `phase1-dataset-build`'s dataset exists at real training volume under `data/study_area/dataset/<split>/<class>/`, with a manifest recording path/period/class/split/coordinates per example.

## Goals / Non-Goals

**Goals:**
- Produce a working Random Forest baseline and CNN candidate, evaluated on the same test split with the same metrics, so the comparison is fair.
- Keep the evaluation honest: report whichever model wins, and treat a Random Forest win as informative, not as a signal to keep tuning the CNN until it wins.
- Execute the generalization and WorldCover cross-checks designed in `phase1-dataset-build`, which were deferred because they need a trained classifier to run against.

**Non-Goals:**
- No Grad-CAM in this change. It needs a trained CNN to attach to, and is its own change with its own evaluation criteria (heatmap coherence), not a metric this change reports.
- No production-grade hyperparameter search. A reasonable, documented configuration for each model is enough to make the comparison meaningful; exhaustive tuning is not required to answer "does the added complexity help."
- No packaging of the final bosque-to-non-bosque change map as a deliverable. This change classifies each date; diffing two classified dates into a change map is downstream work.

## Decisions

**Random Forest trains on per-pixel features, not on flattened patches.** RF doesn't benefit from the 33x33 spatial window the CNN uses; feeding it flattened patches would just be a slower, higher-dimensional version of the same per-pixel decision, not a fairer comparison. RF gets each pixel's own 13 channel values (12 Sentinel-2 bands + NDVI), extracted from the dataset's patch centers, keeping training on the same underlying example set as the CNN without needing a separate data pull.

**CNN architecture stays small and custom, not a pretrained backbone.** Consistent with the decision already recorded in `docs/METODOLOGIA_PIPELINE.md`, "6. Justificación de cada modelo": a large pretrained backbone would make Grad-CAM's heatmaps harder to interpret and would make the "does the CNN's complexity earn its keep" question less honest, since most of that complexity wouldn't have been learned from this project's own data.

**The 5 seeds vary model-internal randomness, not the underlying data split.** `dataset_loader.load_pixel_features`/`PatchDataset` always read the same fixed train/val/test split (from the one `08_assemble_dataset.py` run); `seed` only controls RF's bootstrap/feature-sampling randomness and the CNN's weight initialization plus augmentation. This is deliberate — holding the test set fixed makes the RF-vs-CNN comparison apples-to-apples, rather than conflating model variance with split variance — but it means the 5-run spread reported here measures each model's own training stability, not sensitivity to which physical patches happened to land in which split. Re-running `08_assemble_dataset.py` itself (a new spatial-block assignment) would be the way to test that second, different question, and hasn't been done.

**Operational classifier selection is a distinct question from the accuracy comparison, and depends on Grad-CAM even though Grad-CAM is out of scope here.** The accuracy comparison above answers "does the CNN's spatial context earn a measurable accuracy edge over per-pixel spectral features" — the answer, at this data volume, is no (see 4.2 in `tasks.md`). But `land-cover-classifier`'s downstream consumers include Grad-CAM: this project's core auditability requirement (per-prediction visual evidence, `docs/FOUNDATION.md`), which needs a differentiable model with spatial activation maps to attach to. Random Forest cannot support Grad-CAM under any implementation — it is non-differentiable and has no spatial representation of a prediction to explain — so this is not a gap that more engineering closes. Given the CNN carries no meaningful accuracy cost when tied with RF (macro-F1 0.778 vs 0.773, within the pre-registered noise margin), the CNN — not RF — is designated the operational classifier that Grad-CAM, the temporal-comparison change, and the carbon-estimation change build on. RF's result is not discarded; it remains the documented baseline/comparison finding from Group 4. This only reverses if a future re-run shows RF meaningfully outperforming the CNN (beyond the tie margin, not just failing to be beaten) — in that case the real accuracy cost would outweigh the interpretability benefit, and Grad-CAM would need to be scoped as a diagnostic tool rather than a production dependency. Group 5 (Filadelfia + WorldCover) runs the CNN as the classifier under test accordingly, with Random Forest run alongside for a cheap side-by-side reference.

**Reopened 2026-09-11, closed 2026-09-13 (see tasks.md 4.4 for the full evidentiary record).** The original "CNN carries no meaningful accuracy cost" premise was contested by the Filadelfia held-out result (RF beating the CNN there). Broadening the evidence — two more held-out regions (Bahia Negra, Pozo Colorado), a training-volume scale-up to rule out a data-volume explanation, a mechanistic diagnosis of the Filadelfia failure, and a 5-seed rerun of all three held-out checks to separate real effects from single-run noise — resolved this: **the CNN wins or ties in 3 of 4 evaluated contexts (AOI, Pozo Colorado, Bahia Negra) and loses only in Filadelfia**, where the loss traces to a specific, understood mechanism (the CNN misreads narrow/fragmented forest strips, e.g. agricultural-colony windbreaks under ~330m wide, because it learned "bosque" partly as a large-contiguous-canopy spatial pattern — RF doesn't have this failure mode since it reads only the center pixel). **CNN remains the operational classifier**, since MARTA's actual deployment target (the Corazón Verde del Chaco AOI) is not a fragmented-colony landscape. This is now a settled decision, not provisional — but the Filadelfia-type failure mode is a documented limitation: any future application to a landscape with that structural pattern should cross-check against Random Forest rather than trust the CNN alone.

**"Meaningful" outperformance is defined before training, not after seeing results.** To avoid post-hoc rationalizing a small CNN edge as a win, the design fixes the evaluation criterion in advance: run both models across 5 random seeds, score macro-averaged F1 on the test split for each run, and call the CNN a genuine winner only if its mean macro-F1 exceeds Random Forest's mean by more than one pooled standard deviation across those 5 runs. Full hyperparameter values (batch size 32, Adam at lr=0.001, up to 100 epochs with early stopping at 10 epochs without validation improvement, dropout 0.3-0.5, rotation/flip augmentation only, RF at 300-500 trees with unbounded depth) are documented in `docs/METODOLOGIA_PIPELINE.md`, "3.1 Clasificación de cobertura" — not repeated here, this section is the decision rule, that doc is the reference values.

## Risks / Trade-offs

- **[Risk] The dataset's real training volume (200/class/period, 1,200 total) is still small for a CNN, especially split three ways (train/val/test) across 3 classes.** → Mitigation: this is exactly why the evaluation criterion above requires a margin beyond single-run noise, and why the Random Forest baseline matters: if the CNN can't beat RF at this volume, that's itself a valid, reportable data point about how much volume this task needs.
- **[Risk] The Filadelfia generalization check could show the classifier performs meaningfully worse there than on the case-study AOI's own test split.** → Mitigation: this is the outcome the check exists to catch. Report it as-is; it would motivate widening the training sample geographically in a future change, not something to hide or explain away here.
- **[Trade-off] Fixing the CNN architecture as "small and custom" trades away some ceiling on CNN performance for interpretability and honesty of the comparison.** Accepted deliberately, same rationale as `docs/METODOLOGIA_PIPELINE.md`'s existing note on this.
